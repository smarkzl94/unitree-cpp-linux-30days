# 2026-08-22 · Day 05 · Lambda 调度器 + 软链/du

## 今日目标
- Linux：硬链 / 软链；`tree` / `find`；`du -sh`
- C++：lambda 当比较器；`std::sort` + `snapshot_sorted`；知道 `std::function` 能存、有代价

## 核心知识点（3–7 条）
1. lambda：`[捕获](参数) { 函数体 }`。值捕获是副本；引用捕获不延长寿命
2. 比较器必须严格弱序，不要写 `<=` / `>=`
3. `std::sort` + lambda 一眼能看出排序规则，比手写选择排序短
4. `remove_if` 只把要留的挤到前面，必须再 `erase`（erase-remove）
5. 每个 lambda 是独一无二的无名类型；`std::function` 能存，但可能堆分配、难以内联
6. 硬链：同一 inode 的第二个名字；软链：存路径，目标没了就悬空
7. `du -sh .`：这个目录一共占多少盘

## 代码要点 / API
- `week1-cpp-basics/day05-lambda-scheduler/Scheduler.h` `.cpp` `main.cpp`
- 增删逻辑与 Day04 相同；多出来的是 `snapshot_sorted`
- 构造时传入 lambda 可换大顶 / 小顶
- Linux：`ln` / `ln -s` / `ls -li` / `du -sh`

## 易错点 / 坑
- `[&]` 捕获局部变量再把 lambda 存起来 → 悬空
- 比较器写 `<=` → `std::sort` 未定义行为
- `remove_if` 忘了 `erase` → 尾巴还在
- 热路径不要无脑 `std::function`；能模板 / 直接 lambda 就别先上它
- 没有 `tree` 用 `find . -maxdepth 2` 或 `ls -R`

## 面试口述（2 题）
1. Q：值捕获和引用捕获差在哪？
   A：值捕获是副本，对象没了副本还在。引用捕获不延长寿命，挂出去会悬空。
2. Q：`remove_if` 为什么还要再 `erase`？
   A：它只把要留的挤到前面，尾巴还在。必须再 `erase` 砍掉后半段。
