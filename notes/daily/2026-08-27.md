# 2026-08-27 · Day 09 · MPMC 有界队列 + nice/ulimit

## 核心知识点（3–7 条）
1. MPMC = 多生产者多消费者；正确性仍用同一把 mutex
2. 有界：满了生产者也 `wait`，所以 `push` 也要 `unique_lock`；满了阻塞不覆盖
3. 一把 cv 用 `notify_all`（空等和满等都可能要醒）
4. 序号 0..N-1；消费者本地记录，join 后合并校验
5. nice 越大越客气；`ulimit` 是当前 shell 上限（n 文件 / u 进程 / s 栈）
6. 无界 queue 会涨到 OOM，不是 push 立刻失败

## 代码要点 / API
- `week2-concurrency/day09-mpmc/BoundedQueue.h`：`push` / `wait_and_pop` / `shutdown`

- Linux：`linux-notes.md`（NI 真实输出可后补）

## 易错点 / 坑
- `push` 仍用 `lock_guard` → 满了没法 wait
- `notify_one` 可能叫醒同类
- 校验 set 多线程无锁；先析构再 join
- 把 ulimit 当成全系统；nice 越大当成优先级越高

## 面试口述（2 题）
1. Q：怎么证明 MPMC 不丢不重？  
   A：全局唯一序号；每人本地记录；join 后查齐 N 且无重复。记录结构本身不能有竞争。
2. Q：有界和无界怎么选？`lock_guard` 为啥今天 push 不够？  
   A：不能丢的任务用有界+阻塞。满了生产者要 wait，必须 `unique_lock`。
