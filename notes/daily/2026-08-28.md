# 2026-08-28 · Day 11 · atomic + lscpu / 缓存行

## 今日目标
- Linux：`lscpu`、缓存行、真共享 vs 伪共享
- C++：多线程 `++` 对比裸 int / mutex / `atomic`；何时不要无锁

## 核心知识点（3–7 条）
1. 普通 `++` 是读-加-写三步；无锁会交错、丢更新
2. mutex：临界区同时只有一个线程，所以 `++` 不会被拆开
3. `std::atomic`：这一次加减本身完整（`fetch_add` / `load` / `store`）；默认 `seq_cst`
4. `volatile` 只约束编译器，不能替代 `atomic`
5. 队列等多字段、要 `wait` 的，仍用 mutex+CV，不要无锁
6. 缓存行（常见 64B）是硬件同步块；无关变量挤一行会伪共享

## 易错点 / 坑
- 把 `volatile` 当多线程开关
- 两个 `atomic` 当成一笔事务
- 把「无锁」当成一定更快、更好写

## 面试口述（2 题）
1. Q：`volatile` 能替代 `atomic` 吗？  
   A：不能。volatile 防编译器省略读写；atomic 才保证多线程这一次操作完整和可见性。
2. Q：什么是伪共享？什么时候不该上无锁？  
   A：不同变量在同一缓存行，核间来回作废。多字段不变量、需要 wait、还没证明锁是瓶颈时不要无锁。
