# 2026-08-30 · Day 13 · 控制消费者延迟/丢包 + tail -f

## 今日目标
- Linux：`>` / `>>` / `2>&1`、`tail -f`；测延迟不要每帧打日志
- C++：100Hz 生产 + 50Hz 取最新；延迟均值、seq 间隙、覆盖次数分开报

## 核心知识点（3–7 条）
1. `>` 只动 stdout（1）；`2>` 是 stderr；`> file 2>&1` 先重定向 1 再让 2 跟着走
2. `tail -f`：先看末尾，文件多一行终端再多一行
3. 控制可以比生产慢，只要最新；Day06 的 `pop` 拿最旧，要循环倒空
4. 延迟 = `now - frame.ts`（同一 `steady_clock`）；`size()` 不是延迟
5. `gap_drop`（seq 跳号）和 `overwrite`（环满覆盖）分开；50Hz vs 100Hz 间隙大、覆盖可为 0
6. 两线程抢 RingBuffer 用 mutex；读 `overwrite` 也要锁
7. 每秒一行要更新 `last_print`，否则每拍都打

## 代码要点 / API
- `week2-concurrency/day13-control-consumer/main.cpp`：`pop_latest`、producer/consumer
- 复用 Day06 `RingBuffer.h`
- Linux：`linux-notes.md`

## 易错点 / 坑
- `pop` 是 `bool pop(T&)`，不是 `tmp = buf->pop()`
- 不写 `last_print = now` 会刷屏
- 每帧 `cout` 会扭曲延迟测量

## 面试口述（2 题）
1. Q：控制循环为什么常常只要最新？  
   A：力矩/姿态跟当前世界走；中间帧可丢，换固定周期和最新数据。
2. Q：丢包怎么报才不混？  
   A：seq 间隙 vs 缓冲覆盖分开；策略丢要标明。队列长度不是延迟。
