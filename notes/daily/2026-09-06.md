## 核心知识点（3–7 条）
1. 先问进程在不在、STAT、CPU 高不高、卡在哪个 syscall
2. `ps` 快照；`top` 直播；`strace -p` 贴到已运行进程；gdb 看用户态
3. CPU 低 + 卡住 → 先 strace（read/futex），不要先猜算法
4. Z → 父 wait，不杀僵尸；测速不要一直开 strace
5. 日志 Error 必看，Info 启动/退出/每秒一行；多线程一把 mutex 护一行
6. Day18 handler 只改 atomic，退出后再打「bye」

## 面试口述（2 题）
1. Q：进程卡住了怎么查？  
   A：ps 看在不在和 STAT → top 看 CPU → strace 看 syscall → 像锁/逻辑再 gdb。
2. Q：strace 和 gdb 怎么分工？日志为什么不能每帧打？  
   A：strace 看内核对话，gdb 看变量和栈。100Hz Info 会拖垮磁盘和锁，延迟数字全假。
