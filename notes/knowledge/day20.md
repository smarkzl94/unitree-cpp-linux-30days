# Day20 · 可观测性：strace / ps / top

日期：2026-09-06

## 为什么学这个
线上慢/卡死时，先看「进程在干什么、卡在什么系统调用」。

## 核心知识
1. **`ps` / `top`/`htop`**：CPU、内存、线程数、状态（R/S/D/Z）。
2. **`strace`**：跟踪系统调用与信号；看卡在 `read`/`futex`/`poll` 等。
3. **读 strace**：频繁小 I/O、反复失败的调用、阻塞点。
4. **和 gdb 分工**：strace 看系统交互；gdb 看用户态逻辑。
5. **性能直觉**：是算力不够还是锁等待还是 I/O。

## 易错点
- strace 本身有开销，测性能时慎用
- 只看 CPU 忽略 D 状态（磁盘等待）
