# 项目目标

模拟真机遥测链路：

```text
传感器线程 --100Hz--> RingBuffer --> 控制/处理线程 --> TCP 上报最新状态
                              ^
                         Ctrl+C 优雅退出（Day18）
                         定长头协议（Day23）
                         日志可关（Day20/25）
```

不是四个无关作业，是同一份代码在 `week4-project/telemetry-hub/` 里逐日加厚。

## 分日焦点（和讲义对应）

- **Day24**：接通产线。有界内存，网络慢时覆盖旧遥测，客户端看见不断更新的最新状态。边跑边用 `top`/`ss`。
- **Day25**：控制线程做轻处理（滤波或异常检测）；日志可开关。Linux 侧搞清 journald 或自己轮转。
- **Day26**：冲到目标频率，记下延迟与丢包，修 **1 个** 性能点。压测时用 `top`/`perf stat`。
- **Day27**：别人能按 README 跑起来；`strip`/`ldd`/`run.sh`；简单断线重连。

## 贯穿四天的设计原则

1. **只要最新**：发送端可只保留 latest frame，避免越积越多。
2. **线程职责单一**：产、消、网分离，用 RingBuffer / 最新槽连接。
3. **背压**：网络慢时覆盖旧遥测，而不是无限队列。
4. **可观测**：频率、延迟、丢包；日志默认不刷每帧。
5. **优雅退出**：统一 `running` + notify + join + close。
6. **断线重连**：client 循环 connect；server 接受新连接（Day27 简单版即可）。
