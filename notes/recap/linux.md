# Linux 命令速查

按主题归类。左边命令，右边作用。带 ★ 的常用、面试也容易被问。

---

## 1. 走路：目录与查看

| 命令 | 作用 |
|------|------|
| `pwd` | ★ 打印当前工作目录（我在哪） |
| `cd 路径` | 切换目录 |
| `cd ..` | 回上一级 |
| `cd ~` | 回家目录 |
| `ls` | 列出当前目录下的文件/子目录名 |
| `ls -l` | ★ 详细列表：权限、所有者、大小、时间 |
| `ls -a` | 显示隐藏文件（`.` 开头的） |
| `ls -la` | ★ 上面两个合起来，最常用 |
| `ls -R` | 递归列出子目录内容 |
| `man 命令` | 查手册；空格翻页、`q` 退出、`/词` 搜索、`n` 跳下一个 |

---

## 2. 权限与归属

| 命令 | 作用 |
|------|------|
| `ls -l` | 看权限，最左那一列 |
| `chmod +x 文件` | ★ 加执行位，脚本能 `./` 跑 |
| `chmod 644 文件` | 设成 `rw-r--r--`（普通文件） |
| `chmod 755 文件` | ★ 设成 `rwxr-xr-x`（脚本 / 目录） |
| `chown 用户:组 文件` | 改所有者和所属组 |
| `./脚本.sh` | ★ 当程序启动，**需要** `x` 位 |
| `sh ./脚本.sh` | 交给 sh 解释执行，**不需要** `x` 位 |

权限位：类型 + 三组 rwx。`r` 读，`w` 写；对文件 `x` 是执行，对目录 `x` 是能否 `cd`。`644` = 4+2/4/4；`755` = 4+2+1/4+1/4+1。

## 3. 进程与线程

| 命令 | 作用 |
|------|------|
| `ps` | ★ 进程快照，拍一张就不动了 |
| `ps aux` | 进程名单：所有用户 + 用户列 + 含无终端 |
| `ps -ef` | 进程快照，完整格式，好看 PPID |
| `ps -eLf` | ★ 按**线程**列出（一行一个 LWP）；`-L` 必须大写 |
| `top` | ★ 按进程直播 CPU/内存；`q` 退出 |
| `top -H` | ★ 按**线程**直播 |
| `top -H -p <PID>` | 只看某一个进程里的线程 |
| `pgrep -a 程序名` | 按名字查 PID 和命令行 |
| `kill PID` | ★ SIGTERM，请它自己退出 |
| `kill -9 PID` | SIGKILL，内核直接干掉；卡住时先不要用 |

`ps aux` 一行一个进程；`ps -eLf` 一行一条线程。写成 `-elf`（小写 l）是 long，不按线程拆。堵在 `wait` 时 CPU 可以很低。

## 4. 重定向、管道与盯日志

| 命令 | 作用 |
|------|------|
| `命令 > 文件` | ★ stdout 进文件，**覆盖**（只动 1 号） |
| `命令 >> 文件` | stdout **追加** |
| `命令 2> 文件` | ★ 只有 stderr（报错） |
| `命令 2>> 文件` | stderr 追加 |
| `命令 > 文件 2>&1` | ★ 正常输出和报错都进同一文件（必须先 `>` 再 `2>&1`） |
| `命令A \| 命令B` | ★ 管道：A 的 stdout 接到 B |
| `命令 2>&1 \| 命令B` | 报错也进管道 |
| `tail 文件` | ★ 看文件**末尾**（默认最后 10 行） |
| `tail -n 50 文件` | 最后 50 行 |
| `tail -f 文件` | ★ follow：先打当前末尾，文件多一行终端再多一行；Ctrl+C 停 |

`>` 接到**文件**，`|` 接到**下一个程序**。测延迟不要每帧写日志。

## 5. 找东西与统计

| 命令 | 作用 |
|------|------|
| `grep "词" 文件` | ★ 搜文件**内容**里匹配的行 |
| `grep -n` | 给匹配行加**行号** |
| `grep -R` | ★ 递归搜子目录 |
| `grep -c` | 只输出匹配**行数** |
| `grep -E "A\|B"` | 扩展正则 |
| `find . -name "*.cpp"` | ★ 按**文件名**找路径 |
| `find . -maxdepth 2` | 只往下找两层 |
| `wc -l` | ★ 数行数 |
| `wc -w` / `wc -c` | 数单词 / 字节 |
| `find . -name "*.cpp" \| wc -l` | 数**文件个数** |
| `find . -name "*.cpp" \| xargs grep -n "词"` | 先按名字找文件，再搜内容 |

`grep` 找内容，`find` 找名字。

## 6. 链接与磁盘占用

| 命令 | 作用 |
|------|------|
| `ln 原文件 新名` | 硬链接：同一 inode |
| `ln -s 原文件 新名` | ★ 软链接：存的是路径 |
| `ls -li` | ★ `-i` 显示 inode |
| `tree` | 树状看目录（很多环境没装） |
| `du -sh .` | ★ 当前目录合计占多少盘 |
| `du -h --max-depth=1` | 下一层各子目录各占多少 |

硬链：删原名，别的硬链还在内容还在。软链：目标删了就悬空。

## 7. `/proc` 与 CPU

| 命令 | 作用 |
|------|------|
| `ls /proc` | 内核暴露的状态入口 |
| `cat /proc/cpuinfo` | CPU 型号、逻辑核（细表） |
| `cat /proc/meminfo` | 内存；剩余优先看 MemAvailable |
| `nproc` | ★ 逻辑 CPU 个数 |
| `lscpu` | ★ 逻辑核、插座、超线程、各级 cache 的摘要 |
| `lscpu \| grep -i cache` | 只看缓存相关行 |
| `getconf LEVEL1_DCACHE_LINESIZE` | ★ L1 数据缓存行大小（字节），x86 常见 64 |

`/proc` 是内核伪装成文件。缓存行是硬件同步块。

## 8. 脚本

| 命令 | 作用 |
|------|------|
| `#!/usr/bin/env bash` | shebang |
| `set -euo pipefail` | ★ 失败即退、未定义变量报错、管道任一段失败算失败 |
| `dirname "$0"` | 脚本自己所在目录 |
| `echo $?` | ★ 上一条退出码，`0` 成功 |
| `chmod +x x.sh` + `./x.sh` | 加执行位再跑 |

## 9. nice 与 ulimit

| 命令 | 作用 |
|------|------|
| `nice -n 10 ./程序` | ★ 启动时 NI=10（越大越客气，越不容易抢 CPU） |
| `nice -n -5 ./程序` | NI=-5 更急；普通用户常没权限 |
| `renice -n 15 -p <PID>` | ★ 改**已经在跑**的进程的 nice |
| `ulimit -a` | ★ **当前 shell** 的全部资源上限（不是整机永久配置） |
| `ulimit -n` | 最多多少文件描述符（n 文件） |
| `ulimit -u` | 最多多少用户进程/线程（u 进程） |
| `ulimit -s` | 栈大小（s 栈） |

nice 大约 -20（最急）～ 19（最客气），默认约 0。只改自己的测试程序。

## 10. gdb / strace

| 命令 | 作用 |
|------|------|
| `gdb ./程序` | 用调试器**启动**程序 |
| `gdb -p <PID>` | ★ 挂到已经卡住的进程 |
| `(gdb) info threads` | ★ 列出线程（`*` 是当前） |
| `(gdb) bt` | backtrace：当前线程调用栈 |
| `(gdb) thread N` | 切到线程 N，再 `bt` |
| `(gdb) thread apply all bt` | ★ 所有线程各打一份 bt（死锁首选） |
| `strace -p <PID>` | 打印系统调用 |
| `strace -f -p <PID>` | ★ follow 子进程/线程 |

gdb 的 thread 是 OS 线程。用户态锁睡着时内核常见 **futex** / `FUTEX_WAIT`。

## 11. 墙钟

| 命令 | 作用 |
|------|------|
| `date` | ★ 本地墙钟（几点几分，可被 NTP 改跳） |
| `date -u` | UTC |
| `date +%s` | Unix 秒（1970-01-01 起） |
| `timedatectl` | ★ 本地/UTC、时区、NTP 是否同步 |

测间隔、频率、延迟用程序里的单调时钟（`steady_clock`），不要用 `date` 做分母。

---

## 12. CMake 与 ldd

| 命令 | 作用 |
|------|------|
| `cmake -S . -B build` | ★ **配置**：源码在当前目录，生成到 `build/` |
| `cmake --build build` | ★ **编译链接** |
| `./build/目标名` | 运行编出来的程序 |
| `ldd ./build/目标名` | ★ 看 ELF 运行时 `.so`；`not found` = 缺库 |

只改 `.cpp` → 再 `--build`。改了 `CMakeLists.txt` → 先重新 `-S -B` 再 `--build`。  
`ldd` 只对 Linux ELF（WSL 里编的程序）。Windows `.exe` 不是同一套。

## 易错清单

| 现象 | 原因 / 正确做法 |
|------|-----------------|
| `>` 把文件清空了 | `>` 是覆盖，追加用 `>>` |
| `2>&1 > f` 报错没进文件 | 要先 `> f` 再 `2>&1` |
| 管道里看不到报错 | 管道只接 stdout，写 `2>&1 \|` |
| `./x.sh` Permission denied | 少了 `x`：`chmod +x` |
| 能 `ls` 不能 `cd` | 目录缺 `x` |
| `ps -elf` 看不到线程 | 小写 `l` 是 long；要 `-eLf` 的大写 **L** |
| `top` 里 CPU 很低以为没跑 | 可能在 `wait` / 等锁 |
| 改了 `.cpp` 还去 `-S -B` | 多余；只需 `--build` |
| `ldd` 对着 `.exe` | 到 WSL 对 ELF 做 |
| `date` 测采样率 | 墙钟会跳；间隔用单调时钟 |
| `nice` 越大当成越急 | 越大越客气 |
