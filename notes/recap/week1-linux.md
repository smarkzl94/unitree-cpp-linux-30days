# Week1 Linux 命令速查（Day01–Day07）

按主题归类。左边命令，右边作用。带 ★ 的是本周最常用、面试也最容易被问的。

---

## 1. 走路：目录与查看（Day01）

| 命令 | 作用 |
|------|------|
| `pwd` | ★ 打印当前工作目录（我在哪） |
| `cd 路径` | 切换目录 |
| `cd ..` | 回上一级 |
| `cd ~` | 回家目录 |
| `ls` | 列出当前目录下的文件/子目录名 |
| `ls -l` | ★ 详细列表：权限、所有者、大小、时间 |
| `ls -a` | 显示隐藏文件（`.` 开头的） |
| `ls -la` | ★ 上面两个合起来，最常用 |
| `ls -R` | 递归列出子目录内容 |
| `man 命令` | 查手册；空格翻页、`q` 退出、`/词` 搜索、`n` 跳下一个 |

## 2. 权限与归属（Day01 / Day04）

| 命令 | 作用 |
|------|------|
| `ls -l` | 看权限，最左那一列 |
| `chmod +x 文件` | ★ 加执行位，脚本能 `./` 跑 |
| `chmod 644 文件` | 设成 `rw-r--r--`（普通文件） |
| `chmod 755 文件` | ★ 设成 `rwxr-xr-x`（脚本 / 目录） |
| `chown 用户:组 文件` | 改所有者和所属组 |
| `./脚本.sh` | ★ 当程序启动，**需要** `x` 位 |
| `sh ./脚本.sh` | 交给 sh 解释执行，**不需要** `x` 位 |

权限位读法：类型 + 三组 rwx。

| 位 | 对文件 | 对目录 |
|----|--------|--------|
| `r` (4) | 可读内容 | 可列出里面有什么 |
| `w` (2) | 可改内容 | 可在里面增删、改名 |
| `x` (1) | 可当程序执行 | ★ 可 `cd` 进去 |

`644` = 4+2 / 4 / 4；`755` = 4+2+1 / 4+1 / 4+1。

## 3. 进程（Day02）

| 命令 | 作用 |
|------|------|
| `ps` | ★ 进程快照，拍一张就不动了 |
| `ps aux` / `ps -ef` | 详细进程列表（PID、命令、属主） |
| `top` | ★ 持续刷新 CPU / 内存；按 `q` 退出（不是 `exit`） |
| `kill PID` | ★ 发 SIGTERM，请进程自己退出，能跑析构、关文件 |
| `kill -9 PID` | 发 SIGKILL，内核直接干掉，来不及清理 |

一句话：`ps` 是照片，`top` 是直播；`kill` 是请你走，`kill -9` 是拔电源。

## 4. 重定向与管道（Day03）

| 命令 | 作用 |
|------|------|
| `命令 > 文件` | ★ stdout 重定向到文件，**覆盖** |
| `命令 >> 文件` | stdout 重定向到文件，**追加** |
| `命令 2> 文件` | ★ stderr（报错）重定向，覆盖 |
| `命令 2>> 文件` | stderr 追加 |
| `命令 > 文件 2>&1` | ★ 正常输出和报错都进同一个文件（顺序不能反） |
| `命令A \| 命令B` | ★ 管道：A 的 stdout 接到 B 的 stdin |
| `命令 2>&1 \| 命令B` | 让报错也进管道（管道默认只走 stdout） |

`>` 接到**文件**，`|` 接到**下一个程序**。

## 5. 找东西与统计（Day03）

| 命令 | 作用 |
|------|------|
| `grep "词" 文件` | ★ 搜文件**内容**里匹配的行 |
| `grep -n` | 给匹配行加**行号**（不是「只搜几行」） |
| `grep -R` | ★ 递归搜子目录 |
| `grep -c` | 只输出匹配**行数**，不打印内容 |
| `grep -E "A\|B"` | 扩展正则，一次筛多个词 |
| `find . -name "*.cpp"` | ★ 按**文件名**找路径 |
| `find . -maxdepth 2` | 只往下找两层（没有 `tree` 时代替） |
| `wc -l` | ★ 数行数（word count 的 line） |
| `wc -w` / `wc -c` | 数单词数 / 字节数 |
| `find . -name "*.cpp" \| wc -l` | 数**文件个数**（管道喂的是文件名） |
| `grep -R "TODO" . \| wc -l` | 数**匹配行数** |
| `find . -name "*.cpp" \| xargs grep -n "operator="` | 先按名字找文件，再在里面搜内容 |

`grep` 找内容，`find` 找名字。别搞反。

## 6. 链接与磁盘占用（Day05）

| 命令 | 作用 |
|------|------|
| `ln 原文件 新名` | 硬链接：新名和原文件指向**同一个 inode** |
| `ln -s 原文件 新名` | ★ 软链接：新名里存的是**通往原文件的路径** |
| `ls -li` | ★ `-i` 显示 inode 编号，用来验证硬链是不是同一个 |
| `ls -l`（看软链） | 第一位是 `l`，后面箭头指向目标 |
| `tree` | 树状看目录结构（很多环境没装） |
| `du -sh .` | ★ 当前目录**合计**占多少盘（`-s` 汇总，`-h` 人类可读） |
| `du -h --max-depth=1` | 下一层每个子目录各占多少 |

硬链：删掉原名字，只要还有别的硬链，内容还读得到。软链：原文件删了就**悬空**，`cat` 会失败。硬链一般不能链目录、不能跨分区。

## 7. `/proc`：问内核要状态（Day06）

| 命令 | 作用 |
|------|------|
| `ls /proc` | 列出内核暴露的状态入口（各进程目录、cpuinfo、meminfo…） |
| `cat /proc/cpuinfo` | 看 CPU 型号、逻辑核 |
| `cat /proc/meminfo` | 看内存总量 / 空闲 / 可用（单位常见 kB） |
| `nproc` | ★ 直接给出整机**逻辑 CPU 个数** |
| `grep -c "^processor" /proc/cpuinfo` | 同上，手工版 |
| `grep -E "MemTotal\|MemAvailable\|MemFree" /proc/meminfo` | 只筛这三行 |
| `ls -l /proc/self` | `/proc/self` 是软链，指向**当前进程**的 `/proc/<pid>` |

`/proc` 不是磁盘目录，是内核把系统状态伪装成文件；`cat` 等于当场问内核。看剩余内存优先 **MemAvailable**（含可回收缓存），MemFree 会偏小。

## 8. 脚本（Day04 / Day07）

| 命令 | 作用 |
|------|------|
| `#!/usr/bin/env bash` | shebang：告诉系统用哪个解释器跑 |
| `set -e` | ★ 任一命令失败立刻退出（别让编译失败后还跑旧二进制） |
| `set -u` | 用到未定义变量就报错 |
| `set -o pipefail` | 管道中任一环失败，整条管道算失败 |
| `set -euo pipefail` | ★ 上面三个一起，脚本开头标配 |
| `dirname "$0"` | ★ 脚本自己所在目录（`./x.sh` 里的相对路径是相对**当前工作目录**，不是脚本目录） |
| `echo $?` | ★ 上一条命令的退出码，`0` 表示成功 |
| `chmod +x x.sh` + `./x.sh` | 加执行位再跑；报 Permission denied 就是少了这步 |
| `bash x.sh` | 不加执行位也能跑的退路 |

## 易错清单

| 现象 | 原因 / 正确做法 |
|------|-----------------|
| `>` 把文件内容清空了 | `>` 是覆盖，追加要用 `>>` |
| `2>&1 > f` 报错没进文件 | 顺序反了。`2>&1` 复制的是「**此刻**」1 指向的地方，要先 `> f` 再 `2>&1` |
| 管道里看不到报错 | 管道只接 stdout，要写 `2>&1 \|` |
| `find ... \| wc -l` 数出来比想象小 | 它数的是**文件个数**，不是代码行数 |
| `grep -n` 以为是「只看 n 行」 | `-n` 是加行号；限制条数用 `head` |
| `./x.sh` 报 Permission denied | 少了 `x` 位：`chmod +x`，或改用 `sh ./x.sh` |
| `sh hello.sh` 找不到文件 | 还在家目录。先 `cd` 到脚本目录，或写 `sh ./hello.sh` |
| 能 `ls` 但不能 `cd` 进目录 | 目录缺 `x` 位 |
| 软链 `cat` 失败 | 目标被删了，链接悬空 |
| 看内存以为快满了 | 看错了 MemFree，应该看 MemAvailable |
