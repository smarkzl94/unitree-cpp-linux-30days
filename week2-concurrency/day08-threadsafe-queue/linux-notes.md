## 今日命令

| 命令 | 作用 |
|------|------|
| `ps aux` | 进程名单，快照；所有用户 + 用户列 + 含无终端进程 |
| `ps -eLf` | 所有进程按**线程**列出（一行一个 LWP），完整格式，快照 |
| `ps -eLf \| grep <程序名>` | 只看某个程序的线程行（可能多行，每行一条 LWP） |
| `top` | 按进程直播 CPU/内存，`q` 退出 |
| `top -H` | 按线程直播 |
| `top -H -p <PID>` | 只直播某一个进程里的线程 |
| `pgrep -a <程序名>` | 按名字查 PID，并打印命令行 |

## 小考

### 1. `ps aux` 里 a、u、x 各干什么？

- a：all，所有用户的进程，不限于当前终端里自己的
- u：user-oriented 显示格式（USER、%CPU、%MEM 等列），不是权限
- x：把没有控制终端的进程也列出来（不是 `chmod +x`）

### 2. `ps -eLf` 三个选项各干什么？中间字母大小写写错会怎样？

- `-e`：every，所有进程
- `-L`：列出 LWP（轻量级进程 = 线程），一行一条线程
- `-f`：full，完整格式
- 写成 `-elf`（小写 l）：变成 long 长格式，仍一行一个进程，不按线程拆

### 3. 同一进程为什么会有多行？PID / LWP / NLWP 各是什么？

- 多行原因：`-L` 一行是一条线程；同一进程有多条线程就会多行
- PID：Process ID，进程号，同一进程相同
- LWP：这条线程自己的 id
- NLWP：Number of LWP，这个进程一共有多少条线程

### 4. 主线程的 LWP 和 PID 通常是什么关系？

主线程的 LWP 常常等于这个进程的 PID。再 `std::thread` 出来的工人 LWP 是新号，PID 仍相同。

### 5. 对比表

| 命令 | 粒度 | 刷新 | 每一行是什么 |
|------|------|------|--------------|
| `ps aux` | 进程 | 快照 | 一个进程 |
| `ps -eLf` | 线程 | 快照 | 一条线程（LWP） |
| `top` | 进程 | 直播 | 一个进程 |
| `top -H` | 线程 | 直播 | 一条线程 |

### 6. 堵在 `wait_and_pop` 时，`top -H` 里 CPU 很低，代表没在跑吗？

不代表没在跑。线程还在，只是在等条件变量（`cv.wait`），不占 CPU。有人 `push` 并 notify 后才会醒。低 CPU ≠ 没运行。

### 7. 只盯某一个多线程进程的 `top` 命令？怎么退出？

- 命令：`top -H -p <PID>`（可用 `pgrep -a <程序名>` 先查 PID）
- 退出：按 `q`

## 口述自检（学完能不看稿说）

1. `ps aux` vs `ps -eLf`：前者一行一个进程；后者一行一条线程（同一 PID 可多行，看 LWP/NLWP）。都是快照。
2. `top` vs `top -H`：都是直播；默认按进程，`-H` 按线程，CPU 算到每条线程上。
