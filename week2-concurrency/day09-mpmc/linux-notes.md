## 今日命令

| 命令 | 作用 |
|------|------|
| `nice -n 10 ./程序` | 启动时把 nice/NI 设为 10（更客气，更不容易抢 CPU） |
| `nice -n -5 ./程序` | 启动时 NI=-5（更急；普通用户常没权限） |
| `renice -n 15 -p <PID>` | 把**已经在跑**的进程 PID 的 nice 改成 15 |
| `ulimit -a` | 列出**当前 shell** 的全部资源上限 |
| `ulimit -n` | 最多能开多少文件（文件描述符，含 socket/日志） |
| `ulimit -u` | 最多多少用户进程（很多系统里线程也算） |
| `ulimit -s` | 栈大小（常为 KB） |
| `top` 里的 NI 列 | 该进程的 nice 值；`renice` 后应能看见变化 |
| `ps aux` | 进程快照；所有用户 + 用户列 + 含无终端进程 |
| `ps -ef` | 进程快照；完整格式，方便看 UID/PPID/命令 |

## 小考

### 1. `ps aux` 是快照还是直播？列的是「这个终端里的进程」还是更广？

快照（敲一次出一张表，不自己刷新）。不是只限当前终端：`a`+`x` 含其他用户、无终端的后台进程。

### 2. `ps aux` 和 `ps -ef` 是不是一回事？差在哪？

用途差不多（都是进程快照），不是同一套列。`aux` 好看 USER/%CPU/%MEM；`-ef` 好看 PPID、完整 CMD。都按进程，不是按线程。

### 3. `nice` 数值越大越怎样？常见范围？默认大概是多少？

- 越大：越客气，越不容易抢 CPU（调度优先级更低）
- 范围：约 -20（最急）～ 19（最客气）
- 默认：大约 0

### 4. `nice` 和 `renice` 差在哪？

`nice`：启动程序时带上优先级。`renice`：改已经在跑的那个 PID。

### 5. `ulimit -a` 看的是什么？对谁生效（整个系统还是当前 shell）？

当前这个终端（shell）的资源上限，以及它拉起的进程。**不是**整台机器的永久配置。

### 6. `ulimit -n` / `-u` / `-s` 各限制什么？

- `-n`：**n**ofile，文件描述符个数
- `-u`：**u**ser processes，进程数（常含线程）
- `-s`：**s**tack，栈大小

口诀：n 文件，u 进程，s 栈。`-a` = all。

### 7. 有界队列满了阻塞，和 `ulimit` 是同一类什么设计？无界 `queue` 有什么风险？

都是**有界资源**：满了要阻塞或失败，不能假想无限。无界 `queue` 的 `push` 通常不会立刻失败，内存会一直涨直到 OOM。

### 8. 今天应不应该 `renice` 别人的进程？

不应该。只改自己的测试程序。
