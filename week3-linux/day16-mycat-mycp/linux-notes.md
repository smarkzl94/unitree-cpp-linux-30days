# Day16 · Linux 笔记（strace 看 open/read/write）

日期：2026-09-02

程序读写文件时，真正干活的是内核。用户态 ↔ 内核的这一跳叫系统调用。`strace` 把每次调用的名字、参数、返回值打出来。

---

## 要点

- **系统调用**：程序求内核帮忙（打开文件、读、写）。`strace` 听的是这些对话，不看 C++ 变量。
- **`-e` 是过滤器。** 今天盯 `open,openat,read,write`。现代 glibc 打开文件常常是 **`openat`**，只过滤 `open` 会漏。
- **等号右边是返回值。** fd（如 3、4）；`read`/`write` 是实际字节数。`read = 0` 是 EOF；`-1` 是出错（后面有 errno 名字）。
- **短读很正常**：最后一次 `read` 几乎一定小于缓冲。按返回值干活，不要每次 1 字节（系统调用次数会爆炸）。
- **和 gdb 的分工：** `strace` 看和内核说了什么；`gdb` 看你代码里的行号和变量。

常用命令：

- `strace -e open,openat,read,write ./程序 参数`
- `strace -c ./程序 参数`：每种调用多少次（看缓冲是否太大/太小）
