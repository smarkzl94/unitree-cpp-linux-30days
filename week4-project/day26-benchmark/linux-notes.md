## 压测时看什么

- Day24 的 `top`/`ss` 是空载基线。今天把频率拉到目标后再看：CPU、最热线程、RSS、NLWP。
- `top -H -p PID`：哪条线程热。瞬时会抖，看 5～10 秒。
- CPU 随频率略涨：正常。一核打满但帧率上不去：忙等、锁、或日志。
- RSS 持续爬：无界队列或泄漏。NLWP 在压测中不该再涨。
- `ss -tnp` 的 Send-Q 堆着：对端不读或发太勤，该只发 latest，不是加长队列。

## 不要和测速混用的东西

- **不要开 `strace` 测 P99**：每个 syscall 被拦，延迟和 CPU 都假。strace 是排障。
- **不要用 Debug+ASan 当正式数字**：插桩很慢。测速 Release，正确性另用 ASan 短跑。
- `perf stat` 有就看 10 秒：context-switches 极高像在锁/cv 上打转；instructions 很多但帧很少像在打日志/拷贝。没有 `perf` 就 `top` + 程序自己的 Hz/延迟。不要为装内核工具耗掉今天。

## 三套数字对不上才有故事

| 来源 | 告诉你 |
|------|--------|
| 程序每秒摘要 | Hz、丢包、P50/P99 |
| `top` | 谁热、内存、线程数 |
| `perf` / `ss` | 空转还是网络堆 |

例：P99 高 + Send-Q 堆 → 发太勤或 client 慢 → 修 latest 覆盖，不修滤波算法。
